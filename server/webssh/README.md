# Web SSH

Терминал сервера в браузере. Открываешь секретную ссылку, вводишь логин и пароль от SSH и работаешь как в обычном SSH-клиенте: `htop`, `nano`, `mc`, вставка и копирование. На телефоне внизу есть ряд клавиш Esc, Tab, Ctrl, Alt, стрелки, ^C.

## Поставить

Зайди на сервер по SSH под root и вставь:

```sh
curl -fsSL https://raw.githubusercontent.com/splithillz/one/main/server/webssh/install.sh | sh
```

В конце команда напечатает ссылку вида `https://IP:ПОРТ/секрет/` и отпечаток сертификата. Та же команда потом обновляет Web SSH, а ссылка и настройки остаются прежними.

| Что | Команда |
|---|---|
| Свой порт вместо случайного | `curl -fsSL …/install.sh \| PORT=8443 sh` |
| Показать ссылку ещё раз | `webssh info` |
| Новая ссылка, старая перестанет открываться | `curl -fsSL …/install.sh \| sh -s new-link` |
| Удалить всё | `curl -fsSL …/install.sh \| sh -s remove` |

Нужен Linux с systemd на x86_64 или arm64: Debian, Ubuntu, CentOS, Alma, Rocky. Нет curl — та же команда с `wget -qO-` вместо `curl -fsSL`.

## Как войти

Открой ссылку. Браузер предупредит, что сертификат не подтверждён: он самоподписанный, так и должно быть. Нажми «Дополнительно» → «Перейти на сайт». Отпечаток SHA-256 из вывода установки должен совпасть с тем, что браузер показывает в сертификате. Логин и пароль те же, что в SSH.

## Почему это не дыра

- **Паролей Web SSH не знает.** Логин и пароль уходят в sshd этого же сервера по 127.0.0.1 и проверяются им как при обычном входе по SSH.
- **Секретная ссылка.** Без неё сервер отвечает 404 на любой адрес, форму входа сканеры не видят. В ссылке 144 случайных бита.
- **HTTPS.** Пароль не идёт по сети открытым текстом.
- **Перебор.** 5 неверных паролей за 15 минут закрывают вход с этого IP на 15 минут.
- **Без прав.** Сервис работает от пользователя `webssh` в песочнице systemd: писать может только в `/var/lib/webssh`, `/home` и `/root` не видит. Дыра в нём не даст root — root даёт только верный пароль от SSH.
- **Ключ sshd сверяется** с `/etc/ssh/ssh_host_*_key.pub`, так что процесс, занявший порт SSH, пароль не получит.

## Настройки

Файл `/etc/webssh/webssh.env`, после правки — `systemctl restart webssh`.

| Переменная | Что |
|---|---|
| `WEBSSH_LISTEN` | порт HTTPS, например `:8443` |
| `WEBSSH_SSH` | адрес sshd, установка находит его сама (`127.0.0.1:22`) |
| `WEBSSH_HOSTS` | IP или домен для ссылки и сертификата, если IP сервера не виден на его интерфейсах |
| `WEBSSH_CERT`, `WEBSSH_KEY` | свой сертификат вместо самоподписанного (файлы должен читать пользователь `webssh`) |

Секретная ссылка и сертификат лежат в `/var/lib/webssh`.

## Если не работает

- `systemctl status webssh` и `journalctl -u webssh -n 50` — там видно входы, ошибки и блокировки.
- Страница не открывается — порт закрыт в панели хостинга (облачный файрвол). ufw, firewalld и iptables установка открывает сама.
- «Неверный пользователь или пароль» для root при верном пароле — в sshd стоит `PermitRootLogin prohibit-password`. Войди обычным пользователем или разреши root вход по паролю.
- «Не получилось подключиться к SSH» — sshd не слушает адрес из `WEBSSH_SSH`.

## Сборка

`./build.sh` собирает `releases/webssh-<версия>-linux-{amd64,arm64}.gz` и обновляет `releases/webssh.latest`, откуда их берёт установщик. Go нужной версии подтянется сам по `go.mod`.

Внутри: Go, [xterm.js](https://github.com/xtermjs/xterm.js) 6 (MIT, лицензия в `web/vendor/LICENSE.txt`), шрифт Onest (OFL, `web/fonts/OFL.txt`).
